# 0011. Sign-in of the generated apps

- Date: 2026-10-24
- Deciders: Maintainers

## Status

Accepted

## Context

All three apps were open to all users. ADR 0002 reserved the section
`auth`, with the entity that holds the users. The apps must not show or
change data before a sign-in, and the definition must not hold
passwords or secrets.

The FastAPI app is an API for other clients. The Next.js app renders
pages and runs server actions on the server. The React app has only
mock data and no server.

An identity provider (OIDC) needs an external service in each test and
each local run. A sign-in with a user name and a password needs only
the app and its database.

## Decision

- The section `auth` names the user entity, a required and unique user
  name field (`string` or `email`), the public pages, the public
  operations, and the time of a session (`session_hours`). Version 0
  of the section has only the sign-in with a password.
- The back ends store the password hashes (scrypt, with a random salt)
  in a table `credentials`, apart from the records of the user entity,
  so that no endpoint of the entity returns them.
- A session is a signed text (HMAC-SHA256 with `AUTH_SECRET`) with the
  user ID and the end time. The apps use only the standard library of
  their language, and need no new package.
- FastAPI: `POST /auth/sign-in` gives a bearer token, `GET /auth/me`
  gives the user, and `PUT /auth/password` changes the password. Each
  operation that is not public needs a valid token (401 else).
  `python -m app.cli set-password <user name>` sets a password.
- Next.js: the page `/sign-in` sets an `httpOnly` cookie. Each page that
  is not public goes to the sign-in page without a session, and each
  server action that is not public gives an error. With
  `SEED_PASSWORD`, the seed gives each seed user a password.
- React: the app has no server, so it cannot protect data. It shows the
  sign-in flow with the mock users and the password `password`, and
  each page that is not public needs a sign-in.

## Consequences

- The apps are closed by default, and the public parts are explicit.
- An app cannot run without `AUTH_SECRET` for the sign-in. The compose
  files ask for it.
- There is no sign-up, no password reset, and no external identity
  provider. A later version of the section can add them.
- The sign-in of the React app is a demonstration, not a protection.
- The roles and the permissions of the users are a separate section
  (`access`).
